release. Packages stay `org.apache.fop`; the fork and Apache FOP must never share a classpath.

## Changes since 2.11-docx4j.7

- **An SVG graphic loads only the external resources embedded in it as `data:` URLs** (`fop/CR-028`, option
  `svg-embedded-resources-only`, on by default; the twenty-seventh capability). A `file:`, `http:` or other
  reference from an SVG's `image`, `use`, `tref`, font or stylesheet is refused, the graphic is not drawn and an
  `svgNotBuilt` event says why. Batik's rule, which Apache FOP applies, admits a resource on the document's host,
  and a document laid out from a file base URI, the usual case, has the same null host as every file on the
  machine, so an SVG could read a local file into the output; FOP's own `image` bridge on the PDF and PostScript
  paths applied no rule at all. After Apache POI's fix of the same shape (apache/poi#1452). docx4j's own SVG is
  `data:` only and needs nothing; a consumer whose SVG references files relative to the FO sets
  `<svg-embedded-resources-only>false</svg-embedded-resources-only>` or
  `FopFactoryBuilder.setSvgEmbeddedResourcesOnly(false)`. Test `SVGExternalResourceSecurityTestCase`. Gate: PASS
  (b287 on r47, 0 movers, every event count equal; no corpus document references an external SVG resource, so
  nothing was refused). Upstream: JIRA and pull request drafted, the option off by default there.
- **Thin borders stay visible at screen zoom** (`fop/CR-029`, Enterprise CR-001 §6.6 item 52; no option, no
  capability). FOP drew each border side as a line inside a clip giving it its share of the corners, and for a
  collapsed border between table cells only the cell's own half, so a 0.5pt rule was drawn through clips 0.24pt
  wide. Poppler (Okular, Evince) widens a thin line to a whole device pixel but not a clip, so table rules vanished
  and came back as the reader zoomed. A side that is solid, opaque and square-cornered, whose neighbouring sides are
  absent or solid in its colour, is now drawn as the same line without the clip; other sides keep it. Only painting
  changes, never layout; PostScript output is pixel for pixel the same at 1200 dpi. Gate: PASS (b286 on r48, 0
  movers, every event count equal; the docx4j pricing document's rules solid at every zoom from 60 to 144 dpi).
  Upstream: JIRA and pull request drafted.
