# docx4j-fo-renderer 2.11-docx4j.7

Released to Maven Central on 2026-10-16 by Jason from the pushed branch at the version commit `ecaa37c40`, tagged
`v2.11-docx4j.7` there; verified from Central (the sixth release in `docs/developer/releasing.md`; core jar sha256
`4161643c1cc8eb27a530a924dcc6fdef12ca875a3309fcdcc98f3b000bd04680`). Follows 2.11-docx4j.6 (2026-10-09). Prepared
on 2026-10-15; two fixes found by Jason in the sample went in before the push (§11.20 and §11.21 of `fop/CR-024`,
below). docx4j's `docx4j-export-fo` builds against the released `.6` until the docx4j session bumps it, gated on
the published jar against b273; whether docx4j 17.3.3 ships on `.7` is Jason's call. The runbook is
`docs/developer/releasing.md`.

`docx4j-fo-renderer` is a modified distribution derived from Apache FOP, maintained for docx4j's
docx-to-PDF path. Apache FOP is a trademark of the Apache Software Foundation; this is not an Apache
release. Packages stay `org.apache.fop`; the fork and Apache FOP must never share a classpath.
Coordinates `org.docx4j:docx4j-fo-renderer`, `-core`, `-events`, `-util`.

## Changes since 2.11-docx4j.6

- **Apache `main` merged at c2d7e0aca (2026-10-08)** (`fop/CR-027`). Eight commits since the previous base
  (ab5d6eba6): three are the fork's own fixes come back (FOP-3348, FOP-3349, FOP-3356, byte-identical);
  FOP-3357 adds a Bengali script processor; FOP-3351 allows `afp:page-group=false` on the last page; FOP-3352
  guards an empty last glyph (the fork keeps its general form, any empty glyph, FOP-3339); FOP-3331 places a float
  as wide as its containing block in the flow and fixes a float's position inside a block-container. Two changes
  to FOP-3331's in-flow path: FOP-3353's fix (the fork's pull request #126), so that a float whose child is a
  block-container is not put in the flow whatever its width; and a float with `fox:float-offset` written never goes
  in the flow, keeping the placement `2.11-docx4j.6` gave docx4j's floats. Gated through docx4j (b220): 0 movers on
  the four corpora and the 270 probes; one event count moved, a Bangla document no longer warning of a missing
  syllabizer, FOP-3357 supplying one, its pages unchanged.

- **A line is beside a side float when its box, as a word processor draws it, crosses the float's band**
  (`fop/CR-024` §11.3, from Word's readings of the nine page-anchored picture probes). At the band's top that is
  the text's bottom edge, at the foot the pitch top less the half-leading below; a line whose box lies below the
  foot stays where it is, with no clearance. FOP tested the line's pitch box at both ends, so a line whose leading
  alone crossed the band could differ from Word's by one line. Gated through docx4j (b233, b235, b238, b241, b244,
  the controls of the obstacle gates): 0 movers on the four corpora and the probes.

- **A clearance to a float's foot belongs to the page the edge lies on** (`fop/CR-024` §11.7). The content that did
  not fit below the foot, going to the next page, took the clearance with it and began that far down the page;
  `startPart` now drops a pending clearance when it opens a new page. This guards `clear` and a top-and-bottom
  object at a page's foot too. Found on corpus document 13544, whose second page began 240pt down.

- **A block read again after a float's edge serves no break-before again** (`fop/CR-024` §11.6). Served again it came
  back alone, and the flow, finished from the first reading, lost the block's content; found under docx4j's layout
  managers on corpus document 3475, whose page-anchored logo's page was drawn with one line.

## Hooks since 2.11-docx4j.6

- **`obstacles-in-the-line`** (`fop/CR-024` phase A, Enterprise CR-001 item 11): `fox:wrap` (`square`,
  `top-and-bottom`), `fox:wrap-sides` (`both`, `left`, `right`, `largest`) and `fox:wrap-distances` (before, after,
  start, end) on an absolutely positioned `fo:block-container`. The lines of the page the container lands on wrap
  around it as around a side float whose area is already drawn: the container's layout manager registers an
  obstacle, the page breaker meets the box that holds it, sets the band against the page's body and the part's
  column, narrows the column by the side rule (phase A lays a line in one piece, so `both` is laid as `largest`, the
  wider side), and takes the start edge at the first legal break before a line would cross the band, where orphans
  and widows keep no break, through a break element of infinite penalty that only such an edge may use; the foot
  ends it as a float's foot does; `top-and-bottom`, or no room on the side the rule names, clears the column to the
  foot. A band that begins above the box is honoured from its top by reading the page again from its start, or by
  taking the page's start as the edge when the band covers it; a clearing band that would push its own anchor past
  the page's foot makes the page break before the anchor, which lands below the object on the next page, as a word
  processor moves an object with its anchor; and the page's obstacles are a set, the lines narrowed by every
  obstacle whose band holds them, the foot of one the start of the rest. A band whose top falls inside the first
  line after an edge is beside that line, and a clearing one extends the clearance (§11.18); the lines beside an
  obstacle keep the FO's widows and orphans, where Apache FOP relaxes both to 1 beside a float (§11.19);
