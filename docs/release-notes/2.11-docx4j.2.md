# docx4j-fo-renderer 2.11-docx4j.2 (DRAFT, 2026-09-30)

Draft; closes once `fop/CR-003` passes its re-gate and Jason says the release goes. Sections marked
"pending" name what is on a branch and not yet on `2.11-docx4j.2`. The runbook is
`docs/developer/releasing.md`; the version moves in the `revision` property of the root pom.

`docx4j-fo-renderer` is a modified distribution derived from Apache FOP 2.11, maintained for
docx4j's docx-to-PDF path. Apache FOP is a trademark of the Apache Software Foundation; this is not
an Apache release. Packages stay `org.apache.fop`; the fork and Apache FOP must never share a
classpath. Coordinates `org.docx4j:docx4j-fo-renderer`, `-core`, `-events`, `-util`.

## Fixes since 2.11-docx4j.1

- **A substituted glyph's ToUnicode entry is the characters it stands for** (`fop/CR-002`, Enterprise
  CR-001 §6.6 item 30). A ligature publishes its letters, an Arabic contextual form its letter,
  instead of a private-use code point; search, copy and paste and screen readers get the text the
  document says. No glyph, advance or position moves (gated twice, 598 of 598 corpus documents
  glyph-identical). The second and later glyphs a decomposition produces from one character keep the
  private-use code point, by measured decision (CR-002 §10.2): an empty destination reads as a control
  character in one common reader.
- **ToUnicode selectors no longer drift after a supplementary-plane character** (item 31). An emoji
  or a mathematical alphanumeric in a run no longer makes every later glyph extract as its neighbour.
- **Continuous integration runs on the fork's branch again**: the workflow named the old branch.

## Hooks since 2.11-docx4j.1

- **`gsub-features`** (`fop/CR-001`): `fox:gsub-features`, an inherited property carrying a delta
  such as `-liga` or `-liga +clig`, so Word's ligature setting reaches FOP per run. Inert until the
  producer emits the attribute; gated clean (1 of 603 documents moved, improved).

## Pending, on branches

- **`fop/CR-003`, capabilities `lookup-fallback` and `kerning-flag`.** The lookup fallback goes
  `(script, language)`, `(script, dflt)`, `(DFLT, dflt)` and maps the FO language to its OpenType
  tag first; a font declared `kerning="false"` is positioned without `kern`. This is a rendering
  change: a run with a language set no longer loses a font's ligatures and kerning when the font has
  no system for that language or no `DFLT` table (Carlito, Caladea: every Calibri document through
  docx4j), and a font with a GPOS `kern` feature no longer kerns under `kerning="false"`. Awaiting the
  joint re-gate with CR-005.
- **`fop/CR-005`.** Letter spacing is painted on text that carries glyph position adjustments; before,
  a letter-spaced word in a font that kerns through GPOS was drawn at its bare advances inside an area
  that kept the letter spaces, and the next word's gap absorbed the difference. Merged into the
  CR-003 branch; gates with it.
- **`fop/CR-004`.** A script's default language system shared with a named one is registered under
  `dflt`; DejaVu Sans is kerned under a default language for the first time. Its own gate, after
  CR-003. Order is Jason's.
- **`fop/CR-006`** (design only): a `shared-glyph-tounicode` capability for the Kangxi radical fix
  already shipped in 2.11-docx4j.1, so docx4j can leave CJK fonts' layout tables on.

## For consumers

`Docx4jFop.capabilities()` lists what this jar promises; `Docx4jFop.version()` is the implementation
version from the manifest. docx4j 17.x probes both through `FopCapabilities` and falls back to
reflection on Apache FOP. To go back to Apache FOP, see README, "Going back to Apache FOP".
