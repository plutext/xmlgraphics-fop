# docx4j-fo-renderer 2.11-docx4j.2 (DRAFT, 2026-09-30)

Draft; `fop/CR-003` and `fop/CR-005` merged 2026-09-30 after their re-gate passed; closes when Jason says the release goes. Sections marked
"pending" name what is on a branch and not yet on `2.11-docx4j.2`. The runbook is
`docs/developer/releasing.md`; the version moves in the `revision` property of the root pom.

`docx4j-fo-renderer` is a modified distribution derived from Apache FOP 2.11, maintained for
docx4j's docx-to-PDF path. Apache FOP is a trademark of the Apache Software Foundation; this is not
an Apache release. Packages stay `org.apache.fop`; the fork and Apache FOP must never share a
classpath. Coordinates `org.docx4j:docx4j-fo-renderer`, `-core`, `-events`, `-util`.

## Fixes since 2.11-docx4j.1

- **A substituted glyph's ToUnicode entry is the characters it stands for** (`fop/CR-002`, Enterprise
  CR-001 §6.6 item 30). A ligature publishes its letters, an Arabic contextual form its letter,
  instead of a private-use code point; search, copy and paste and screen readers get the text the
  document says. No glyph, advance or position moves (gated twice, 598 of 598 corpus documents
  glyph-identical). The second and later glyphs a decomposition produces from one character keep the
  private-use code point, by measured decision (CR-002 §10.2): an empty destination reads as a control
  character in one common reader.
- **ToUnicode selectors no longer drift after a supplementary-plane character** (item 31). An emoji
  or a mathematical alphanumeric in a run no longer makes every later glyph extract as its neighbour.
- **A run with a language set no longer loses a font's ligatures, contextual forms and kerning**
  (`fop/CR-003`, capability `lookup-fallback`). The lookup fallback now goes `(script, language)`,
  `(script, dflt)`, `(DFLT, dflt)`, as OpenType layout engines do, and maps the FO language to its
  OpenType tag first; a language the font does distinguish (Turkish) gets its own system. This is a
  rendering change: through docx4j every Calibri document (Carlito has no `DFLT` table) is shaped and
  kerned where it asks for the first time. Gated on 598 documents: still set 408 held, every movement
  the predicted one, 22 scoreboards improved and 4 worse by a fallback font's metrics.
- **A font declared `kerning="false"` is positioned without the GPOS `kern` feature** (`fop/CR-003`,
  capability `kerning-flag`); marks are still positioned. Before, the flag gated only the legacy kern
  table, so a font with a GPOS `kern` feature kerned under both declarations. Plain runs of fonts whose
  `DFLT` kern applied (Nimbus Sans Narrow, P052, DejaVu Serif) stop kerning, as Word's rule says.
- **Letter spacing is painted on text that carries glyph position adjustments** (`fop/CR-005`, Enterprise
  CR-001 item 33). A letter-spaced word in a font that kerns through GPOS was drawn at its bare advances
  inside an area that kept the letter spaces, and the next word's gap absorbed the difference.
- **A format character the font has a zero-width glyph for stays in the text layer** (`fop/CR-007`,
  Enterprise CR-001 item 34): the deprecated controls U+206A to U+206F and the joiners now reach the
  subset and the ToUnicode CMap, as Word's text layer has them; the bidi marks, embeddings and isolates
  stay out, since the text layer is in visual order already and Word drops them too. Ink unchanged.
- **A script's default language system is kept when a named language shares its table** (`fop/CR-004`,
  Enterprise CR-001 item 32). FontForge writes one table for the default and every language whose
  features equal it, and the reader had been aliasing the default away, leaving the script with none;
  the request then fell to the `DFLT` script, which lists whatever the font's author happened to put
  there. Measured consequences on the fork before the fix: DejaVu Sans was never kerned under a default
  language, and its Arabic was never shaped (no contextual forms, no marks); Noto Sans Devanagari lost a
  `dist` lookup; Droid Sans Devanagari, with no `DFLT` script, lost all its shaping. 252 of 1,356 fonts
  installed on the build machine have the shape. Gated: still set glyph-identical, every mover the
  predicted one and toward Word, none worse.
- **Continuous integration runs on the fork's branch again**: the workflow named the old branch.

## Hooks since 2.11-docx4j.1

- **`gsub-features`** (`fop/CR-001`): `fox:gsub-features`, an inherited property carrying a delta
  such as `-liga` or `-liga +clig`, so Word's ligature setting reaches FOP per run. Inert until the
  producer emits the attribute; gated clean (1 of 603 documents moved, improved).

- **`shared-glyph-tounicode`** (`fop/CR-006`): names the Kangxi radical fix shipped in 2.11-docx4j.1, so docx4j
  can leave a CJK font's layout tables on instead of declaring it `advanced="false"`.
- **`lookup-fallback`** and **`kerning-flag`** (`fop/CR-003`): no members; each names a fix a producer
  relies on (see the fixes above), so docx4j can tell whether writing `language` on every block costs it
  shaping, and whether its plain and `+kern` declarations kern only where the run asked.

## For consumers

`Docx4jFop.capabilities()` lists what this jar promises; `Docx4jFop.version()` is the implementation
version from the manifest. docx4j 17.x probes both through `FopCapabilities` and falls back to
reflection on Apache FOP. To go back to Apache FOP, see README, "Going back to Apache FOP".
