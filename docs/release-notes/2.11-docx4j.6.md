# docx4j-fo-renderer 2.11-docx4j.6 (DRAFT)

Draft; closes when Jason says the release goes. Follows 2.11-docx4j.5 (2026-10-07). The runbook is
`docs/developer/releasing.md`.

`docx4j-fo-renderer` is a modified distribution derived from Apache FOP, maintained for docx4j's
docx-to-PDF path. Apache FOP is a trademark of the Apache Software Foundation; this is not an Apache
release. Packages stay `org.apache.fop`; the fork and Apache FOP must never share a classpath.
Coordinates `org.docx4j:docx4j-fo-renderer`, `-core`, `-events`, `-util`.

## Changes since 2.11-docx4j.5

- **`clear` is honoured on a block-level FO after a side float** (`fop/CR-022`; capability
  `clear-after-side-float`). An `fo:block`, `fo:block-container`, `fo:table` or `fo:list-block` whose `clear` names
  the side a float is on ends the float at the break before it and is laid out at the float's foot, full width, as
  CSS clearance places a box below the floats it must not sit beside. FOP read `clear` on `fo:float` only, so a table
  following a text box's anchor paragraph was set beside the box and drawn over it. Content without `clear`, or with
  `clear` on the other side, is set beside the float as before. Gated through docx4j: pending.
