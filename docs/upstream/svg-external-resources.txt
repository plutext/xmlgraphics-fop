Summary
-------
An SVG can read local files into the output; add an option restricting an SVG's external resources to data: URLs

Description
-----------
Batik admits an SVG's external resources (image, use, tref, @font-face sources, stylesheets) through the user agent's
getExternalResourceSecurity. FOP's user agents (SimpleSVGUserAgent, SVGUserAgent, the transcoders') keep
UserAgentAdapter's default, DefaultExternalResourceSecurity: a resource is admitted when its host equals the
document's host, and a file: URL has a null host on both sides. Batik 1.20 adds a check that the protocols match,
which a file: resource beside a file: document passes. The document URL of an fo:instream-foreign-object is the FO's
base URI, and of an external SVG graphic the file's own URI, so for a document laid out from a file base URI, the
command line's case, an SVG may name any file on the machine:

    <use xlink:href="file:///home/user/private.svg#g"/>
    <image xlink:href="file:///home/user/photo.png"/>
    <text><tref xlink:href="file:///home/user/private.svg#t"/></text>

and the fragment, the picture and the text are drawn into the PDF. Measured with a probe FO carrying those three
references, in an inline SVG and in an external one, on FOP 2.12 as released (fop-2.12-bin, Batik 1.20) and on main
at 1301bcf74: from a file: base URI, all three are drawn, inline and as an external graphic. From an http: base
URI, Batik refuses them. Apache POI had the same shape in its SVGUserAgent and fixed it in apache/poi#1452
(2026-10-20) by returning EmbededExternalResourceSecurity, data: URLs only.

The FO's own URLs (external-graphic, basic-link) go through FOP's ResourceResolver, which a deployment restricts;
Batik's loads do not.

Proposed change (pull request to follow)
----------------------------------------
1. An option svg-embedded-resources-only, plumbed like table-border-overpaint: FopFactoryConfig
   .isSvgEmbeddedResourcesOnly(), FopFactoryBuilder.setSvgEmbeddedResourcesOnly(boolean), the configuration element
   <svg-embedded-resources-only>, FopFactory and FOUserAgent getters. Off by default, so nothing changes until a user
   opts in; a deployment rendering untrusted FO turns it on. Whether a later release should default to on is for the
   project to decide.
2. SimpleSVGUserAgent.setEmbeddedResourcesOnly(boolean): when set, getExternalResourceSecurity returns
   EmbededExternalResourceSecurity(resourceURL). SVGUserAgent sets it from the FOUserAgent; ImageConverterSVG2G2D sets
   it from the FopFactory behind the image session context in its hints. Batik's own bridges then refuse anything
   but data: (its SVGImageElementBridge asks the user agent in buildImageGraphicsNode, before FOP's image bridges
   take over in createImageGraphicsNode).
3. The transcoders keep Batik's rule and their KEY_ALLOW_EXTERNAL_RESOURCES hint.

A refused resource surfaces as the existing svgNotBuilt event; the graphic is not drawn, the page is.

Test: SVGExternalResourceSecurityTestCase (in the style of POI's TestSVGImageRenderer): an FO laid out from a
temporary directory with five inline SVGs and five external ones (a rectangle, a data: image, a use of a local
fragment, a file: image, a use of another file's fragment), rendered to PDF (read back with PDFBox) and to PNG; with
the option on the two file rows are blank and four svgNotBuilt events are raised, with it off all ten rows are drawn.
Two existing tests reference pictures from SVG relative to the FO or by a custom scheme and are unaffected with the
option off (the default upstream).

TITLE: FOP-####: option svg-embedded-resources-only, an SVG's external resources restricted to data: URLs

Fixes [FOP-####](https://issues.apache.org/jira/browse/FOP-####).

Batik admits an SVG's external resources (`image`, `use`, `tref`, fonts, stylesheets) through the user agent's
`getExternalResourceSecurity`; FOP's user agents keep Batik's default, same host as the document (and, from Batik
1.20, the same protocol), and a `file:` URL has no host on either side. So for a document laid out from a file base
URI, the command line's case, an inline or external SVG may `use`, `tref` or `image` any file on the machine into
the output: measured on 2.12 and on `main`. Apache POI fixed the same shape in its `SVGUserAgent`
(apache/poi#1452).

**The change.**
- Option `svg-embedded-resources-only` (`FopFactoryConfig`, `FopFactoryBuilder`, `FopConfParser`, `FopFactory`,
  `FOUserAgent`), off by default: nothing changes until a user opts in.
- `SimpleSVGUserAgent.setEmbeddedResourcesOnly(boolean)`: when set, `getExternalResourceSecurity` returns Batik's
  `EmbededExternalResourceSecurity`, `data:` URLs only. `SVGUserAgent` takes it from the `FOUserAgent`;
  `ImageConverterSVG2G2D` from the `FopFactory` behind the image session context in its hints.
- The transcoders keep Batik's rule and `KEY_ALLOW_EXTERNAL_RESOURCES`.

A refused resource is the existing `svgNotBuilt` event; the graphic is not drawn, the page is.

**Test.** `SVGExternalResourceSecurityTestCase`: an FO laid out from a temporary directory, ten rows of 100 by 20
points, five inline SVGs and the same five as external graphics (a rectangle, a `data:` image, a `use` of a local
fragment, a `file:` image, a `use` of another file's fragment), rendered to PDF (read back with PDFBox's renderer)
and to PNG, each row's centre pixel read. With the option on, the two file rows are blank in both outputs and four
`svgNotBuilt` events are raised on the PDF path; with it off, all ten are drawn and no event is raised. A fifth
test checks the user agent alone. With the change, the fop-core suite passes and checkstyle reports 0 violations
[counts to be re-measured on the rebased branch before posting].
