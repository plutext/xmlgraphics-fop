Summary
-------
NoSuchElementException in LMiter.next when a side float's end falls inside a table

Description
-----------
When a side float outlasts the paragraph it is anchored in and the content beside it continues into an
fo:table, the float's end falls between two rows. PageBreaker.handleFloatLayout then reads the element list
again from that break (FlowLayoutManager.getNextKnuthElements with a restart position inside the table).
TableLayoutManager is not restartable (isRestartable() is false, as for the IPD-change restart, which checks
it through AbstractBreaker.containsNonRestartableLM); the generic restart in
BlockStackingLayoutManager.getNextKnuthElements pops the table's child layout manager off the stack and
asks setCurrentChildLM for it, and the table's child iterator, already exhausted, throws:

java.util.NoSuchElementException
    at org.apache.fop.layoutmgr.LMiter.next(LMiter.java:69)
    at org.apache.fop.layoutmgr.AbstractLayoutManager.setCurrentChildLM(AbstractLayoutManager.java:132)
    at org.apache.fop.layoutmgr.BlockStackingLayoutManager.getNextKnuthElements(BlockStackingLayoutManager.java:278)
    at org.apache.fop.layoutmgr.FlowLayoutManager.getNextChildElements(FlowLayoutManager.java:225)
    at org.apache.fop.layoutmgr.PageBreaker.getNextKnuthElements(PageBreaker.java:334)
    at org.apache.fop.layoutmgr.AbstractBreaker.getNextBlockList(AbstractBreaker.java:746)
    at org.apache.fop.layoutmgr.PageBreaker.handleFloatLayout(PageBreaker.java:898)

No output is produced. Minimal FO (A4, 72pt margins):

<fo:block font-family="Times" font-size="12pt" line-height="14pt" space-after="10pt"><fo:float float="right"><fo:block-container width="300pt" height="40pt"><fo:block font-size="0.1pt" line-height="0pt"/></fo:block-container></fo:float>Heading</fo:block>
<fo:table table-layout="fixed" width="200pt" border-collapse="collapse"><fo:table-column column-width="200pt"/><fo:table-body>
  five of: <fo:table-row><fo:table-cell border="0.5pt solid"><fo:block>cell N</fo:block></fo:table-cell></fo:table-row>
</fo:table-body></fo:table>
<fo:block>after</fo:block>

The 40pt float outlasts the heading's 14pt line and its 10pt space; the float's end falls after the second
row. clear="both" on the table makes no difference.

Fix (patch to follow)
---------------------
PageBreakingAlgorithm.considerLegalBreak: a legal break whose previous and next boxes lie inside the same
non-restartable layout manager is not taken as the float's edge; the edge waits for the first legal break
after it. The rows below the float keep the table's width, which the table set once for all its rows, so
nothing is drawn differently from a re-layout at the row, and the paragraph after the table is read again at
full width. Measured: five rows at the table's width, "after" full width below the table. Layout engine test:
float_side-edge-space.xml (fourth sequence). The fop-core suite passes (3853 tests).
